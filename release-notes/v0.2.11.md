# v0.2.11 - Resource Calendar 讀取阻擋解除（HTTP 直連 Graph）

日期：2026-07-23

## 版本目的

在 IT 將 `ad.general@alp.global` 對 `room_nhb4_car@alp.global` 的權限由 Calendar Folder Editor 提升為 Mailbox Full Access 後，重新驗證 Power Automate 是否可讀取 ATA-9627 Resource Mailbox 行事曆事件，並在確認既有動作仍不可行後，找出可行的標準連接器替代路徑。

## 實測過程

### 一、Full Access 委派後重測既有動作（結論：無效）

- Flow：`公務車功能測試-ATA9627事件讀取`（Flow ID `7d66adc8-eccd-4cc0-9ab1-a031a6676df9`）
- `取得行事曆 (V2)`：重新執行後仍只回傳 `ad.general@alp.global` 自身的個人 `Calendar`，未列出 Resource Mailbox。
- `取得事件的行事曆檢視 (V3)`：以一組格式正確的 Exchange Item ID 測試，錯誤由先前的 `ErrorInvalidIdMalformed` 變為 `404 ErrorItemNotFound`（`The specified object was not found in the store.`）。
- 檢查 V3 動作完整參數（含 5 個進階參數：篩選查詢、排序依據、最高計數、略過計數、搜尋），確認**沒有任何可指定「其他信箱」的欄位**。
- 判定：`取得行事曆 (V2)` 與 `取得事件的行事曆檢視 (V3)` 這兩個動作在架構上只能存取連線帳號自己的行事曆，不論授予 Calendar Folder Editor 或 Mailbox Full Access 都無法讀取 Resource Mailbox，非權限問題，是連接器動作本身的限制。
- 附帶完成：確認測試 Flow 已由「開啟／每分鐘排程」變更為「關閉」，解除長期卡住的 P0 待辦。

### 二、驗證 Full Access 對郵件類動作有效

- 建立暫存測試流程 `公務車功能測試-郵件動作參數檢查(可刪除)`。
- `取得電子郵件 (V3)` 動作在進階參數中找到 `原始信箱地址`（mailboxAddress）欄位，填入 `room_nhb4_car@alp.global` 後，`statusCode 200`，成功讀到該資源信箱 Inbox 的真實郵件。
- 證實 Full Access 委派對「郵件類」動作有效；限制只發生在「行事曆類」動作。

### 三、找到正式解法：Office 365 Outlook 連接器內建「傳送 HTTP 要求」

- 同一個 Office 365 Outlook 標準連接器（非 Premium）內有「傳送 HTTP 要求」動作，可直接呼叫 Microsoft Graph 端點。
- 第一次嘗試 `/v1.0/users/room_nhb4_car@alp.global/calendarView?...` 失敗，錯誤訊息揭露白名單限制：

  ```text
  Invalid resource, Allowed values: me,users.
  Invalid Object, Allowed values: messages,mailFolders,events,calendar,calendars,outlook,inferenceClassification.
  ```

- 改用允許清單內的 `calendar/events` 物件，並以 OData `$filter` 做時間區間查詢：

  ```text
  GET /v1.0/users/room_nhb4_car@alp.global/calendar/events?$filter=start/dateTime ge '2026-07-14T00:00:00' and start/dateTime le '2026-07-30T23:59:59'
  ```

- 執行結果：`statusCode 200`，**成功取得 ATA-9627 真實借用紀錄**，欄位完整可用，包含：
  - `subject`：使用事由（例如「Daniel Yen 閻證恩 瑞芳參訪」）
  - `start.dateTime` / `end.dateTime`：借用起訖時間（UTC）
  - `isAllDay`：是否整天
  - `organizer.emailAddress.name` / `address`：借用人姓名與 Email（例如 `daniel.yen@alp.global`）
  - `id`、`iCalUId`：事件唯一識別
  - `lastModifiedDateTime`：最後異動時間
  - `location.displayName`：對應車輛名稱
  - `recurrence`：重複規則（若為重複事件）

## 判定

- M5「Resource Calendar 事件讀取」正式解除阻擋，判定為**通過**。
- 不需要 Power Automate Premium 授權，不需要另外註冊 Azure AD App 或 Logic App。
- 不需要解析郵件 ICS 附件（方案二仍可行但非必要，已驗證僅作為備援）。
- 可以正式進入 `公務車行事曆同步至 SharePoint` 流程建置階段。

## 已知限制與待驗證事項

1. `傳送 HTTP 要求` 的 Graph 端點僅限白名單物件（`messages`、`mailFolders`、`events`、`calendar`、`calendars`、`outlook`、`inferenceClassification`），`calendarView` 不可用，需以 `calendar/events` + `$filter` 取代。
2. 目前僅以 ATA-9627 驗證，Camry（`room_nhb4_car_camry@alp.global`）與 Cross（`room_nhb4_car_cross@alp.global`）尚未逐一重測，理論上原理相同，但需實際跑過一次確認 Full Access 已授權且回應正常。
3. 回傳時間為 UTC，寫入 SharePoint 前仍須依既有防呆規則轉換為 `Asia/Taipei` 顯示時間，原始 UTC 值另存於 `原始開始時間 UTC` / `原始結束時間 UTC` 欄位。
4. `$filter` 對重複事件（recurring series）僅會回傳 `seriesMaster`，若要展開所有個別發生實例，後續需改用 `/calendarView`（不在白名單內，需另評估）或改用 `instances` 端點；MVP 階段先以 `events` 端點涵蓋單次與系列主體事件。
5. 暫存測試流程 `公務車功能測試-郵件動作參數檢查(可刪除)` 已保留在 Power Automate 中作為設定參考，僅手動觸發、不會自動執行，可於正式流程建立後刪除。
