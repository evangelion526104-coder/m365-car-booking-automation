# v0.2.13 - 正式同步流程執行期錯誤修正並完成首次成功執行驗證

日期：2026-07-24

## 版本目的

v0.2.12 完成流程建置並開啟排程後，流程儲存驗證顯示「零錯誤」，但實際排程執行後，運行紀錄（Run History）中的每一筆執行都顯示「失敗」或「測試失敗」，代表流程自開啟排程以來從未真正成功執行過一次。本版本逐一排查並修正造成執行期失敗的四種錯誤，並完成一次端到端的成功執行與 SharePoint 資料驗證。

## 重要發現

儲存時「零錯誤」只代表流程通過語法檢查，不代表執行時邏輯正確。四種錯誤都是儲存時檢查不出來、只有實際執行才會觸發的執行期（Runtime）錯誤。

## 修正內容

### 一、Apply to each 巢狀迴圈參照大括號寫法錯誤（延續 v0.2.12 命名問題，另一種寫法錯誤）

- 兩個 Apply to each 迴圈的 `foreach` 參數本身被誤寫為 `"@{items(...)}"`（大括號包裹），造成型別被強制轉為字串，導致 `InvalidTemplate` 型別不符錯誤。
- 修正為不加大括號的原生運算式 `"@items(...)"`，兩處迴圈皆修正並以程式碼檢視確認。

### 二、SharePoint 篩選查詢使用欄位顯示名稱而非內部名稱

- 「取得多個項目」動作的篩選查詢誤用中文欄位顯示名稱「預約唯一鍵」，SharePoint 回傳「欄位不存在」錯誤。
- 排查 SharePoint 對非英數欄位顯示名稱的內部命名規則：以每個字元的 Unicode 編碼產生 `_xNNNN_` 格式並串接，且內部名稱上限 32 字元（超過會被截斷），OData 查詢時非英數起首的內部名稱前面還會再加上 `OData_` 前綴。
- 以 SharePoint REST API（`/_api/web/lists(guid'...')/fields?$filter=Title eq '預約唯一鍵'&$select=InternalName,StaticName,EntityPropertyName`）取得權威內部名稱，確認正確篩選欄位應為 `OData__x9810__x7d04__x552f__x4e00__x93`。
- 修正篩選查詢後動作恢復正常執行（約 0.3～0.5 秒）。

### 三、條件判斷式大括號寫法錯誤（與第一項同類錯誤，出現在第三處）

- 「條件」動作的判斷式 `greater` 比較誤寫為 `"@{length(...)}"`，造成回傳值型別被轉為字串，與預期的整數型別不符，觸發 `InvalidTemplate` 錯誤。
- 修正為 `"@length(...)"`（不加大括號），並確認條件判斷式所在的「條件」動作屬於結構性動作，程式碼檢視為唯讀，須改由「參數」頁籤 UI 直接編輯運算式。

### 四、「是否整天」欄位型別不符（布林欄位誤寫入中文字串）

- 「建立項目」「更新項目」兩分支的「是否整天」欄位皆誤寫為 `if(equals(...),'是','否')`（回傳中文字串），但 SharePoint 該欄位為布林（Yes/No）型別，觸發 `OpenApiOperationParameterTypeConversionFailed` 錯誤。
- 修正為直接參照行事曆事件原生布林值 `@items('套用至各項_1')?['isAllDay']`，兩分支皆修正。

## 驗證方式與結果

1. 逐一修正並儲存流程，確認「您的流程已準備就緒」且零錯誤。
2. 手動觸發測試執行，運行紀錄首次出現「測試成功」狀態（先前所有歷史紀錄皆為失敗）。
3. 展開執行追蹤逐層確認：外層「套用至各項」（三台車，皆綠色勾選）→ 「傳送 HTTP 要求」→「剖析 JSON」→ 內層「套用至各項 1」→「編輯」「編輯 1」→「取得多個項目」→「條件」→「建立項目」（本次為新事件，條件為假，成功執行；「更新項目」分支正確顯示為略過）。
4. 以 SharePoint REST API 直接查詢清單資料，確認三筆借用紀錄（Altis、Camry、Cross 各一筆對應本次事件）已正確寫入，且「是否整天」欄位型別確認為真正的布林值（`Edm.Boolean` 的 `true`/`false`），非文字字串。
5. 後續排程再次自動執行後，同一批項目的 `Modified` 時間更新但 `Id` 未增加（清單仍僅 3 筆），確認「預約唯一鍵」防重複比對邏輯於新增與更新情境下皆正常運作，未產生重複項目。

## 判定

- 正式流程 `公務車行事曆同步至SharePoint` 至此完成首次真正端到端成功執行，並以 SharePoint 實際資料驗證寫入正確性，判定為**通過**。
- v0.2.12 版本紀錄中「流程儲存驗證零錯誤」之敘述，就流程執行結果而言並不完整；本版本補充說明並修正實際執行期錯誤。
