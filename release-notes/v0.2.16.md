# v0.2.16 - 流程清理、正式化切換與 Concurrency Control

日期：2026-07-27

## 版本目的

v0.2.15 完成事件取消偵測補強邏輯後，遺留三項待辦：確認「我的流程」清單是否有重複項目、將 `是否測試資料` 切換為正式運作邏輯、建立 Concurrency Control。本版本完成上述三項收尾與風險控管工作。

## 本次處理內容

### 一、「我的流程」清單清理

檢視「我的流程」清單時，發現以下問題並逐一處理：

1. **重複流程（已關閉）**：存在第二個同名「公務車行事曆同步至SharePoint」流程（Flow ID `a3357db1-a6f0-47ad-bc8f-e182756e1263`，建立於 2026-07-23），狀態為「開啟」，每 15 分鐘執行一次。展開其執行紀錄確認動作結構僅為早期原型版本——`Recurrence → 車輛清單 → 套用至各項`（內僅含「傳送 HTTP 要求」與「剖析 JSON」，**無任何 SharePoint 寫入動作**）。確認不會與正式流程（Flow ID `b6d1ec5c-0fc5-46c1-85b0-d8d68c72c0ce`）產生資料衝突後，將其關閉（狀態改為「關閉」），避免無意義的背景 Graph API 呼叫。
2. **測試流程仍在背景執行（已關閉）**：`公務車功能測試-資源信箱讀取`與`公務車功能測試-SharePoint清單連線`兩個流程，儘管先前文件（FT-008、FT-011）記載「已關閉，不再排程執行」，實際檢查發現兩者狀態仍為「開啟」，且分別每約 1 分鐘執行一次。已將兩者關閉，避免不必要的 API 呼叫與執行紀錄累積。
3. **暫存測試流程（已刪除）**：`公務車功能測試-郵件動作參數檢查(可刪除)` 為手動觸發類型（非排程），先前版本已多次記錄為待刪除項目；本次確認其與正式流程無關聯後執行刪除。
4. `公務車功能測試-ATA9627事件讀取` 原本即為關閉狀態，未受影響，無需處理。

### 二、`是否測試資料` 切換為正式邏輯

透過「程式碼檢視」比對 SharePoint 欄位內部名稱，定位到正式流程「條件」判斷式兩個分支（`更新項目`、`建立項目`）皆將 `是否測試資料` 欄位硬編碼為 `是`。已分別將兩處的值由 `是` 改為 `否`，確保後續新建立與更新的借用紀錄不再被標記為測試資料。修改後儲存流程，確認「您的流程已準備就緒」，零錯誤。

**已知限制**：此變更僅影響「未來」執行的建立與更新動作；既有已標記為 `是否測試資料 = 是` 的正式測試紀錄（如 Id=1～4）不會被追溯更新，是否需要另行批次修正或保留作為歷史測試紀錄，留待下一步決定。

### 三、建立 Concurrency Control

在 Recurrence 觸發程序的「設定」中啟用「並行控制」，將「平行處理原則的程度」由關閉改為限制並設為 `1`，確保同一時間只會有一個流程執行個體運行；若某次執行時間超過 15 分鐘排程間隔，後續觸發會依序等待而非重疊執行，降低同一時間窗內對 SharePoint 產生重複或競爭寫入的風險（對應 `test-cases/function-test-plan.md` SG-T10）。

同時檢查三個 Apply to each 迴圈（套用至各項、套用至各項 1、套用至各項 2）的「並行控制」設定，確認其預設狀態（關閉）代表**循序執行**，而非平行執行——這與直覺相反：對 Apply to each 而言，「並行控制」關閉才是循序處理，啟用並行控制才是用來自訂平行處理程度（最高 50）。三個迴圈皆維持關閉（循序），因此不需額外調整；這也確保了迴圈內用來記錄本次讀取事件唯一鍵的陣列變數 `CurrentEventKeys` 不會在平行迭代下發生競爭寫入。

## 驗證方式與結果

1. 逐一開啟「我的流程」清單中每個候選重複／測試流程的詳細資料頁，核對「狀態」欄位（開啟／關閉）與「28 天執行歷程記錄」的實際執行間隔，確認其中兩個仍在背景每 15 分鐘或每 1 分鐘執行。
2. 展開重複流程的執行追蹤（測試成功的某次執行），逐層檢視其動作結構與輸出，確認僅為讀取與剖析、未寫入 SharePoint，排除資料衝突疑慮後才予以關閉。
3. 修改 `是否測試資料` 後，儲存流程並確認零錯誤（尚未另行手動觸發驗證實際寫入值，將於下次排程執行時反映）。
4. 儲存 Concurrency Control 設定後，確認「您的流程已準備就緒」，零錯誤。

## 判定

- 「我的流程」清單重複與背景執行問題，判定為**已清理完成**。
- `是否測試資料` 正式化切換，判定為**已完成**（未來紀錄適用；既有紀錄不受影響，屬已知限制）。
- Concurrency Control，判定為**已建立**（觸發層級限制為 1；Apply to each 迴圈確認維持循序執行）。
