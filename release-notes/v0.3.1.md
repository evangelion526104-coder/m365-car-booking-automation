# v0.3.1 - P2 收尾測試補齊：通知時間邊界、後台領鑰、重複預約與唯一鍵驗證

更新日期：2026-07-30

## 背景

P2（公務車借用前 Teams 通知與回覆流程）於 v0.3.0 完成主要功能實作與核心路徑驗證後，仍有 8 項既定測試案例尚待執行。本版本針對這批收尾測試逐一執行並記錄結果。

## 本次新增完成內容

* 依既有測試計畫，執行並補齊 FT-104～FT-107、FT-112、FT-113、SG-T08、SG-T09 共 8 項待測案例。
* FT-104（借用 09:30）／FT-105（08:30）／FT-106（早於 08:00，實測 07:30）／FT-107（整天借用）：於 ATA-9627 行事曆分別建立對應測試事件，經「公務車行事曆同步至SharePoint」流程同步後，SharePoint 預計通知時間之計算結果與「借用前 1 小時、最早 08:00、整天一律 08:00」規則完全相符，4 項全數通過；測試完成後已清除對應之 Outlook 測試事件與 SharePoint 測試紀錄。
* FT-112：以 SharePoint REST API 查詢確認「領鑰狀態」欄位於所有正式紀錄皆正確填寫且可篩選，承辦人可據此判斷是否發放鑰匙，判定通過。
* SG-T08：以既有正式紀錄佐證（兩筆商業發展處 ALP BD用車 紀錄主旨相同、預約唯一鍵／Event ID 不同，SharePoint 正確區分為獨立兩筆），判定通過。
* FT-113：測試並複核目前流程架構後發現，借用事件是以 Editor 委派權限直接建立於資源信箱行事曆，並非透過會議邀請送交資源信箱，因此不會觸發 Outlook 資源信箱原生的雙重預約阻擋機制；現階段系統未在任何層級強制避免同車重複預約，判定為未通過並列為已知限制，待後續評估補強方案（例如流程內加入同車時段重疊檢查）。
* SG-T09（重複資料異常標記）本輪測試循環尚未實際執行，維持待驗證狀態，列為後續待辦。

## 已知限制與待辦

* FT-113（同車重複預約）：未通過，列為已知限制，待 v0.3.2 補強。
* SG-T09（重複資料異常標記）：待驗證，待後續版本執行。

詳見 `test-cases/function-test-plan.md` 最新測試結果與 `CHANGELOG.md` 對應段落。
