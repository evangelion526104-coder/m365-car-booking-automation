# v0.2.12 - 建立正式公務車行事曆同步至SharePoint流程並啟用排程

日期：2026-07-23

## 版本目的

在 v0.2.11 解除 Resource Calendar 讀取阻擋、確認「傳送 HTTP 要求」直連 Graph 可行後，完成三台公務車共用的正式同步流程 `公務車行事曆同步至SharePoint`（Flow ID `b6d1ec5c-0fc5-46c1-85b0-d8d68c72c0ce`），並在驗證零錯誤後正式啟用排程觸發。

## 完成內容

### 一、流程結構

```text
Recurrence（排程觸發，每 15 分鐘）
  → 車輛清單（Compose，三台車的資源信箱與名稱）
  → 套用至各項（Apply to each，外層，逐台車）
      → 傳送 HTTP 要求（GET /v1.0/users/{資源信箱}/calendar/events?$filter=...）
      → 剖析 JSON
      → 套用至各項 1（Apply to each，內層，逐筆事件）
          → 編輯（Compose，計算「預約唯一鍵」= 資源信箱 + "|" + 行事曆事件 ID）
          → 編輯 1（Compose，計算「預計通知時間」）
          → 取得多個項目（SharePoint，以「預約唯一鍵」篩選）
          → 條件（篩選結果筆數 > 0？）
              → 真：更新項目（SharePoint Update item）
              → 假：建立項目（SharePoint Create item）
```

- 三台車共用同一組讀取、解析、寫入邏輯，僅資源信箱與車輛名稱不同（`車輛清單` Compose 提供三筆資料供外層迴圈逐一處理）。
- `更新項目`、`建立項目` 兩個分支填入相同的欄位對應，確保新增與更新資料一致。

### 二、欄位對應（依 `sharepoint/list-schema.md`）

兩個分支皆完整寫入下列欄位：標題、資源信箱、車輛名稱、行事曆事件 ID、預約唯一鍵、借用人姓名、借用人 Email、借用日期、借用起始時間、借用結束時間、最後同步時間、使用事由、是否整天、預計通知時間、iCalUId、顯示時區（`Asia/Taipei`）、Flow 執行 ID、唯一識別來源（`Event ID`）、事件同步狀態（`有效`）、事件最後修改時間、原始開始/結束時間 UTC，以及系統防呆欄位預設值（領鑰狀態 `待通知`、卡片狀態 `未發送`、通知狀態 `未通知`、處理鎖定狀態 `未鎖定`、重複資料檢查結果 `正常`、規範確認狀態 `否`、功能測試結果 `未測試`、已取消 `否`、已失效 `否`）。

- `是否測試資料` 暫時設定為 `是`，作為正式上線前的安全預設值，待最終驗收後再改回 `否`。
- 借用日期／時間一律以 `convertTimeZone(...,'UTC','Taipei Standard Time')` 轉換後寫入，原始 UTC 值另存於「原始開始時間 UTC」「原始結束時間 UTC」供稽核，未直接顯示給使用者。

### 三、排除的設計問題：Apply to each 命名空格轉底線

儲存流程時出現：

```text
InvalidTemplate: The template validation failed: 'The repetition action(s) '套用至各項 1' referenced by 'inputs' in action '更新項目' are not defined in the template.'
```

排查後確認：Power Automate 動作／迴圈的顯示名稱若含空格，從**該動作自身作用範圍以外**以名稱參照時（例如 `items(...)`、`outputs(...)`），空格會被轉換為底線。也就是說巢狀迴圈 `套用至各項 1` 在其他動作的運算式中必須寫成 `items('套用至各項_1')`，而非 `items('套用至各項 1')`。

- 此問題造成「更新項目」動作中約 13 個欄位的運算式一開始誤用空格形式，逐一修正為底線形式後儲存成功、零錯誤。
- 新建立的「建立項目」動作直接採用底線正確格式，未重複此問題。
- 此為 Power Automate 設計工具的命名慣例限制，非本專案邏輯錯誤，記錄於此供後續建立巢狀迴圈時參考，避免重蹈覆轍。

### 四、驗證與啟用

- 兩個分支欄位填寫完成後執行「儲存」，訊息顯示：「您的流程已準備就緒。建議您對其進行測試。」，無 `InvalidTemplate` 或 `無效參考` 錯誤。

- 流程現為每 15 分鐘自動執行一次，正式進入排程運作階段。
