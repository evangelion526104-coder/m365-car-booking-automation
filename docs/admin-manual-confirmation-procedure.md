# 管理員手動確認操作程序

更新日期：2026-08-03

## 適用情境

借用人未透過 Teams Adaptive Card 完成回覆（例如未收到通知、Teams 帳號問題、臨時借用未走通知流程等），但承辦人已透過站外管道（電話、當面、Email 等）確認借用人已知悉並同意公務車使用規範、共乘人數等資訊完整，需由承辦人直接於 SharePoint 後台手動確認，以便判斷是否可發放鑰匙。

## 前提原則

- 手動確認僅適用於承辦人已透過站外管道確實取得借用人同意規範與共乘人數資訊的情況，不得在未確認的情況下直接放行。
- 手動確認為例外流程，非正常路徑；正常情況應優先引導借用人透過 Teams Adaptive Card 自行回覆。

## 需要同步更新的欄位（重要）

依 v0.3.0 開發階段實測發現的教訓：「領鑰狀態」與「通知狀態」兩欄位在正常流程中屬於同一狀態的兩種呈現方式，若手動編輯時只修改其中一項而遺漏另一項，會導致「公務車借用前Teams通知與回覆」流程的觸發條件判斷不一致，可能造成：

- 條件判斷式誤判，系統對同一筆紀錄重複發送 Teams 通知；或
- 已手動確認的紀錄仍被流程視為「待通知」而繼續嘗試發送卡片。

因此，承辦人手動確認時，必須「同時」更新以下欄位，不得只改其中一項：

| 欄位 | 手動確認時應設定的值 | 說明 |
|---|---|---|
| 領鑰狀態 | 已完成確認 | 承辦人確認借用人已知悉規範且共乘人數等資訊完整後填入 |
| 通知狀態 | 已通知 | 避免流程誤判為「未通知」而重複發送 Teams 卡片 |
| 共乘人數 | 依實際確認結果填入 | 若承辦人已口頭確認實際人數 |
| 規範確認狀態 | 是 | 對應借用人已確認知悉規範 |
| Teams 回覆時間 | 留空或填入承辦人手動確認時間 | 可用於區分「借用人自行回覆」與「承辦人代為確認」 |
| 承辦人備註 | 註明手動確認方式與時間（例如：「2026/8/3 承辦人電話確認，借用人已知悉規範」） | 供後續稽核追溯 |

## 操作步驟

1. 於 SharePoint 清單「公務車借用管理」（`https://alpglobal.sharepoint.com/sites/ALP_TW_AD/Lists/List6/AllItems.aspx`）找到對應借用紀錄。
2. 確認該紀錄的「事件同步狀態」為「有效」、「已取消」為「否」，避免對已取消或已失效的預約誤放行。
3. 若「重複資料檢查結果」為「異常」，應先向借用人或相關人員確認是否為同一台車重疊借用，釐清後才決定是否放行；不得直接忽略異常標記。
4. 依上表同時更新「領鑰狀態」「通知狀態」（以及視情況更新共乘人數、規範確認狀態、承辦人備註）。
5. 儲存後建議重新整理頁面確認欄位已正確寫入。
6. 依確認結果決定是否發放鑰匙。

## 常見錯誤（依 v0.3.0 除錯經驗整理，避免再次發生）

- 只修改「領鑰狀態」未同步修改「通知狀態」，導致流程持續每 5 分鐘重複發送 Teams 卡片給借用人（即使借用人已由承辦人代為確認）。
- 修改前未確認「事件同步狀態」與「已取消」欄位，誤放行已被取消或已失效的預約。
- 忽略「重複資料檢查結果 = 異常」的提示，未進一步確認即發放鑰匙，可能造成同車雙重借用。
